# CH32V003 UART IAP Bootloader — Proteus32, Revision 2 (WL_FLASH-safe)

UART-загрузчик для WCH CH32V003F4U6 (Proteus32). Принимает прошивку по USART1
на 460800 8N1 и записывает её в пользовательский flash с 0x08000000, **не
затрагивая область настроек WL_FLASH** (0x08003F00–0x08003FFF).

Спецификация: `BOOTLOADER_TZ.md` (ТЗ v1.0). Дополнений к ТЗ нет.

## Ключевые свойства (revision 2)

- **WL_FLASH неприкосновенен.** Загрузчик стирает/пишет только
  `[0x08000000, 0x08003F00)` (252 страницы × 64 Б). `FLASH_EraseAllPages()` (MER)
  удалён полностью; никакой записи/стирания в `0x08003F00..` не существует.
- **Никакой магии 0x5AA55AA5.** END-команда не выполняет операций с flash
  вообще (раньше стирала 4-ю страницу WL-кольца 0x08003FC0).
- **Структурные границы на стороне загрузчика:** PROM/VERIFY за пределами
  app-области отклоняются с `ERR_RANGE` (0x02) до любого обращения к flash;
  READ (0x84) читает весь user-flash (включая WL) только на чтение.
- **Полноценный VERIFY:** хост передаёт эталонные данные (кадр 0x82 с 64 Б);
  загрузчик сравнивает с flash и возвращает `ERR_VERIFY` (0x03) при несовпадении.
- **Сброс состояния сессии** при ERASE/END — оборванная сессия не «протекает»
  в следующую.
- Размер: **1680 Б** из 1920 Б boot-области (цель ТЗ ≤ 1888 Б, предел 1920 Б),
  контроль — size-гейтом в `build.cmd`.
- Индикация (P2): PC4 (зелёный) + PC7 (красный) — оба горят при входе
  в загрузчик; PC7 мигает ~4 Гц в ожидании и при обмене. Актив-высокий.

## Карта памяти (CH32V003F4U6)

| Область | Адреса | Примечание |
|---|---|---|
| Boot area (загрузчик) | 0x00000000–0x0000077F | отдельная flash 1920 Б, маппится по 0x0 в BOOT-старте |
| — код загрузчика | 0x00000000–0x0000068F | 1680 Б (факт после сборки) |
| — служебная страница | 0x000007C0–0x000007FF | зарезервирована |
| User code flash | 0x08000000–0x08003EFF | 16128 Б — единственная область записи загрузчика |
| **WL_FLASH (настройки)** | **0x08003F00–0x08003FFF** | **только чтение (READ); запись/стирание запрещены** |
| Option Bytes | 0x1FFFF800+ | загрузчиком не трогаются |
| SRAM | 0x20000000–0x200007FF | стек 256 Б + буферы |

## Вход в режим загрузчика

- Питание при **зажатой кнопке** (PC3 прижата к GND) → IAP-режим, опрос UART.
- Питание без кнопки → `IAP_2_APP()` (`RCC_ClearFlag()`,
  `SystemReset_StartMode(Start_Mode_USER)`, `NVIC_SystemReset()`) → старт
  приложения с 0x08000000.
- После команды END 0x83 загрузчик отвечает ACK, ждёт ≥100 мс (дрейн UART)
  и сбрасывается в приложение.

## Протокол UART (v2)

Физика: USART1, 460800 8N1, no flow control, HSI 24 МГц (BRR = 0x34);
PD5 = TX (AF push-pull), PD6 = RX (input pull-up). Stop-and-wait:
следующий кадр — только после ответа на предыдущий.

Кадр запроса: `AA 55 CMD LEN PAYLOAD CK_L CK_H 55 AA`
(CK = (CMD + LEN + ΣPAYLOAD) mod 0x10000, little-endian).

| CMD | Имя | LEN | PAYLOAD | Ответ загрузчика |
|---|---|---|---|---|
| 0x80 | PROM | 0x40 | 64 Б данных | ACK / ERR_RANGE |
| 0x81 | ERASE | 0x00 (+4 Б addr, игнор.) | — | ACK (стирает 252 страницы [0x08000000, 0x08003F00)) |
| 0x82 | VERIFY | 0x40 | 4 Б addr-заглушки + 64 Б эталона | ACK / ERR_VERIFY / ERR_RANGE |
| 0x83 | END | 0x00 (+4 Б addr, игнор.) | — | ACK, пауза ≥100 мс, сброс в приложение |
| 0x84 | READ | 0x04 | addr, u32 LE | `AA 55 84 00 <64 Б> CK_L CK_H 55 AA` |
| прочее | — | — | — | ERR (0x01) |

Коды статуса (базовый ответ `AA 55 00 ST 55 AA`):

| ST | Значение |
|---|---|
| 0x00 | OK |
| 0x01 | ERR (неизвестная команда, сбой flash) |
| 0x02 | ERR_RANGE — выход за app-область [0x08000000, 0x08003F00) |
| 0x03 | ERR_VERIFY — несовпадение данных |

Кадр с неверной контрольной суммой/хвостом — тихий отброс без ответа,
ресинк на `AA 55`.

### Контрольные векторы (из ТЗ 3.5.4, байт-в-байт)

```
ERASE:   AA 55 81 00 00 00 00 08 89 00 55 AA          -> AA 55 00 00 55 AA
PROM:    AA 55 80 40 FF..FF(64) 80 40 55 AA           -> AA 55 00 00 55 AA
VERIFY:  AA 55 82 40 00 00 00 08 FF..FF(64) 8A 40 55 AA -> AA 55 00 00 55 AA
END:     AA 55 83 00 83 00 55 AA                      -> AA 55 00 00 55 AA
READ:    AA 55 84 04 00 3F 00 08 CF 00 55 AA          -> AA 55 84 00 <64 Б> CK 55 AA
Overflow:                                             -> AA 55 00 02 55 AA
```

## Сборка

ОДНА команда (воспроизводимо):

```
build.cmd            # компиляция + линковка + size-гейт
build.cmd clean      # очистка build\
```

Требования: GCC riscv (MounRiver Studio 2: `riscv-wch-elf` (GCC 12)
или `riscv32-wch-elf` (GCC 15); fallback `riscv-none-embed` в PATH).
Скрипт ищет тулчейн в стандартных путях MounRiver; переопределение:
`set RISCV_GCC_BIN=C:\path\to\RISC-V Embedded GCC\bin`.

Флаги: `-march=rv32ecxw -mabi=ilp32e -Os -ffunction-sections -fdata-sections
-nostartfiles -flto -Wall -T Ld/Link.ld --specs=nano.specs --specs=nosys.specs
-Wl,--gc-sections`.

Артефакты: `build/bootloader.bin` (сырой образ boot-области, 0x00000000),
`build/bootloader.elf` (отладка), `build/bootloader.map`.

SDK: заголовки — `SDK_inc/` (skopированы из framework-wch-noneos-sdk,
vendored), исходники — `SDK_src/` (только используемые: flash, rcc, usart).

**Прошивка загрузчика** — только через WCH-Link (SWD/библиотека MounRiver),
в boot-область по 0x00000000.

Size-гейт: падение при >1920 Б, предупреждение при >1888 Б. Текущий размер
выводится при каждой сборке.

## Несовместимость версий

- Скрипт v2.1 (Proteus32 `proteus32_3.py`, сессия B) и `BootUI` до
  синхронизации: старый скрипт шлёт VERIFY с Len=0 — с протоколом v2
  несовместим (загрузчик v2 без данных VERIFY исполнит no-op успешно,
  но READ/статусы недоступны). Поставлять загрузчик и скрипт v2.1 вместе.
- Старый загрузчик (v1): VERIFY-no-op, READ отсутствует, END стирал
  0x08003FC0 и писал магию 0x5AA55AA5. Пару не смешивать с v2.

## История

- **V2.0.0** — WL_FLASH-safe: ERASE постраничный в границах app-области,
  END чистый, guards PROM/VERIFY/READ, статусы 0x02/0x03, READ-команда,
  сброс сессии, LED-индикация, воспроизводимая сборка `build.cmd`
  (размер 1680 Б).
- **V1.0.1** — исходный WCH IAP-пример (MER + магия в END, размер 1860 Б).
